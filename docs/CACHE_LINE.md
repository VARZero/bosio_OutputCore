# BS25: 파라미터형 DDR 읽기 캐시

BS25는 장면 전체를 두 BRAM 뱅크에 복사하던 BS24 구조를 바꿉니다.
팔레트와 타일 디렉터리만 BRAM에 두고, 셀 색 데이터는 DDR에서 필요한
캐시 라인만 읽습니다. 정이십면체 면·타일·셀 주소 계산과 자세 투영은
계속 RTL에서 수행합니다.

## 합성 시 설정

| 출력 코어 파라미터 | 기본값 | 의미 |
|---|---:|---|
| `DDR_CACHE_ENABLE` | 1 | 1은 BS25, 0은 기존 BS24 BRAM 장면 캐시 |
| `CACHE_LINE_BYTES` | 64 | 한 번에 채우는 라인 크기. 16~1024의 2의 거듭제곱 |
| `CACHE_BYTES` | 16384 | 셀 데이터 캐시 총용량. 메타데이터·큐 용량은 제외 |
| `CACHE_WAYS` | 2 | 세트당 라인 수. 1·2·4 지원 |

세트 수는 `CACHE_BYTES / (CACHE_LINE_BYTES * CACHE_WAYS)`이며,
2 이상의 2의 거듭제곱이어야 합니다. 런타임 레지스터로 용량을 변경하는
기능은 없습니다. 변경 후 IP를 다시 패키징하고 비트스트림을 빌드합니다.
M=16 타일은 256바이트이므로 기본 설정에서는 타일당 네 라인입니다.

`varzero_cache_line.v`는 BOSIO와 독립적인 읽기 전용 캐시입니다.
AXI 데이터 폭 32·64·128비트와 응답 메타데이터 폭을 지원합니다.
현재 BOSIO 통합 어댑터의 AXI 데이터 폭은 **32비트**입니다.
교체 정책은 세트별 round-robin이며, 무효한 라인이 있으면 먼저 사용합니다.

## 요청과 응답

요청과 응답은 valid/ready 핸드셰이크를 사용합니다. 요청 주소는 정렬된
32비트 워드 주소이고, `req_user`는 해당 응답까지 보존됩니다. 히트는
최대 클럭당 요청 하나를 처리합니다. 미스 시 정렬된 AXI INCR burst로
라인을 채우고 원래 요청을 다시 처리합니다. 동시에 진행하는 fill은 하나이며,
미스 동안 새 요청은 대기합니다. 오류 응답은 `rsp_error=1`, 데이터 0이고
실패한 라인은 유효하게 등록하지 않습니다.

독립 IP에는 명시적인 prefetch 포트가 있습니다. **현재 BOSIO 어댑터는
이 포트를 사용하지 않고 demand read만 수행합니다.** 타일 전체 선취나
여러 미스의 동시 처리는 후속 확장입니다.

`bosio_ddr_scene_cache.v`는 타일·셀 요청을 FIFO에 저장하고 디렉터리를
조회하여 DDR 주소로 바꿉니다. DDR 지연이나 출력의 backpressure가 있어도
픽셀 순서를 유지합니다. 이전 프레임의 읽기가 모두 끝난 후 다음 프레임을
시작하며, 그 경계에서 장면 주소와 캐시 무효화를 함께 적용합니다.

## 장면과 부분 갱신

장면 형식은 RGB332 팔레트 256워드, 디렉터리 4220워드, 활성 타일의
셀 색 데이터 순서입니다. 셀 데이터 시작은 워드 4476이며 전체 길이는
16워드로 정렬합니다. 전체 갱신 시 하드웨어가 메타데이터 4480워드를 읽고,
다음 프레임부터 새 DDR 장면 주소를 사용합니다.

BS25의 `0x6c=2`는 **완성된 DDR 장면의 주소 전환**입니다. BS24처럼
BPT1 패킷 주소를 직접 넣으면 안 됩니다. Python 드라이버가 BPT1을 검사하고
비활성 DDR 장면 버퍼의 변경 타일만 수정한 다음 주소를 전환합니다.
전환 확인 후 이전 버퍼에도 같은 변경을 반영하여 다음 부분 갱신을 준비합니다.
타일의 활성 여부·디렉터리·팔레트가 바뀌면 전체 갱신을 사용합니다.

각 DDR 버퍼는 최소 64바이트 정렬되고 최대 라인 크기인 1024바이트 단위로
길이를 패딩해야 합니다. 출력 중인 버퍼는 수정하거나 해제하면 안 됩니다.
코어를 끈 후 읽기 큐가 완전히 비었는지도 확인해야 합니다. 제공 드라이버가
이 수명과 전환을 관리합니다.

## 추가 레지스터

기존 자세·센서·AA 레지스터의 위치는 유지됩니다.

| 주소 | BS25에서의 의미 |
|---|---|
| `0x10` | demand cache hit 누적 수 |
| `0x14` | demand cache miss 누적 수 |
| `0x18` | 요청이 대기한 클럭 누적 수 |
| `0x34` | 합성된 라인 바이트 수 |
| `0x38` | 합성된 데이터 캐시 바이트 수 |
| `0x3c` | 합성된 way 수 |
| `0x40` bit 0 | 픽셀 요청과 응답이 모두 비어 있음 |
| `0x44` | 현재 읽고 있는 DDR 장면의 BASE. 주소 전환 완료 확인에 사용 |
| `0x6c` | 1: 전체 메타데이터 로드, 2: DDR 장면 주소만 전환 |
| `0x70` | 수신한 메타데이터 워드 수. BS24의 전체 전송량과 의미가 다름 |
| `0x74` | 최대 셀 데이터 바이트 수 4,321,280 |
| `0x7c` | BS25 식별값 `0x42533235` |

카운터는 32비트로 순환합니다. 드라이버의 `status()`는 식별값에 따라
BS24/BS25를 구분하고 새 캐시 정보를 제공합니다.

## 검증과 한계

`verification/tb_cache_line.v`는 64/128/256바이트 라인, AXI 32/64/128비트,
충돌·응답 대기·무효화·명시적 prefetch를 확인합니다.
`tb_ddr_scene_cache.v`는 메타데이터 로드, 빈 셀, 요청 순서, 출력 대기,
읽기가 남은 상태에서의 전환 방지와 DDR 주소 전환을 확인합니다.
통합 저장소의 `test_ddr_scene_driver.py`는 두 버퍼의 부분 갱신 일치와
잘못된 패킷의 거부, M=32 전체 구면 패킹을 검사합니다.

장면 용량의 BRAM 제약을 제거하는 변경입니다. DDR 대역폭·캐시 미스·ARM
투영 합성 비용은 남아 있으므로 M=32의 실시간 성능을 보장하지 않습니다.
통합 시스템의 기본 M=16과 기존 AA 설정을 유지합니다.
